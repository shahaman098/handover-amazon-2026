# Verified research: Build, Ship, Shape: Amazon Developer Hackathon

## Requirements
- [required/eligibility] Mandatory: register through the event's Devpost site and complete all required submission fields before the deadline.
- [required/eligibility] Mandatory: individual participants must meet their jurisdiction's age of majority. Geographic, promotion-entity, judge, affiliate, family/household, and conflict-of-interest exclusions apply. Named excluded locations include Brazil, Quebec, Russia, Crimea, Cuba, Iran, and North Korea; the list is not exhaustive.
- [required/team] Conditional mandatory: teams and organizations must authorize an eligible representative to submit on their behalf. No official maximum team size.
- [required/track] Mandatory: enter a qualifying primary track and identify the selected primary track(s) and any mini challenges in the submission. Each project can win at most one track prize and one mini-challenge prize.
- [required/artifact] Mandatory: provide a working application newly created or significantly updated during the submission period. For an existing project, explain and demonstrate the qualifying changes.
- [required/platform] Conditional mandatory for Fire TV: run on Fire OS or Vega OS and show functioning software on an actual Fire TV device or accepted emulator/simulator. Framework choice is unrestricted.
- [required/technology] Conditional mandatory for Alexa+: demonstrate a working Agent Skill, a self-hosted MCP server using specification 2025-11-25 or later over Streamable HTTP, or a working simulated Alexa+ experience. The simulation alternative requires source code and a functioning demonstration but no specific SDK, framework, or MCP-shaped interface.
- [required/data] Conditional mandatory for Bee: use actual data recorded and processed through a Bee device or Apple Watch running Bee software via Bee CLI, MCP, or Agent Skills. Code and video must demonstrate actual Bee-data interaction delivering user value. Public onboarding of other Bee users is unnecessary.
- [required/technology] Conditional mandatory for Ring: use a documented Ring API, SDK, simulator, or device and demonstrate the application through an accepted simulator or actual device. Physical hardware is optional.
- [required/technology] Conditional mandatory for Alexa+ nonsimulation, Bee, and Ring: repository code must actually use the qualifying technology through runtime calls, entry points, or loaded agent/flow/MCP configuration. README mentions alone do not qualify. Alexa+ simulations and Fire TV have their separately specified alternatives.
- [required/artifact] Mandatory: submit a text description explaining project features, functionality, and operation.
- [required/artifact] Mandatory: provide a GitHub repository containing all necessary source code, assets, and clear setup/run instructions. Use either a public repository with a detectable open-source license or a private repository shared with the specified Amazon and Devpost reviewers.
- [required/artifact] Conditional mandatory for private repositories: share with Amazon reviewers knmeiss, giolaq, anishamalde, mosesroth, emersonsklar and the specified Devpost reviewer before the deadline. The supplied evidence redacts the Devpost email address; resolve it from the official source. Invitations require acceptance and expire after seven days.
- [required/demo] Mandatory: provide a public YouTube or Vimeo demonstration video and its submission-form link, showing the project functioning on the intended accepted platform. Target less than three minutes; judges need not watch beyond three minutes. Third-party media and trademarks require appropriate rights.
- [required/artifact] Mandatory: for every tool, API, or SDK used, explain its purpose, strengths, shortcomings, onboarding experience, and whether and why the entrant would use it again.
- [required/other] Mandatory: make the project available free of charge and without testing restrictions to sponsor, administrator, and judges through the judging period ending November 20, 2026 at 12:00 Pacific Time. Provide credentials for private websites when applicable. The FAQ permits a locally runnable repository and video without continuous hosting.
- [required/artifact] Mandatory: provide submission materials in English or supply English translations, including the video, description, documentation, and testing instructions.
- [required/eligibility] Mandatory: satisfy originality, ownership, privacy, and intellectual-property requirements; obtain authorization for third-party APIs, SDKs, data, and media, and comply with open-source licenses. Sponsor/administrator financial or preferential support restrictions also apply.
- [required/other] Conditional mandatory when entering multiple submissions: each must be unique and substantially different from the entrant's other submissions.
- [required/sponsor] Conditional mandatory if entering AWS Builder: document qualifying AWS use and describe the services and their use in product feedback. Kiro Crew development use alone qualifies without a separate AWS runtime service.
- [required/artifact] Conditional mandatory if entering Open Source: provide a new additional licensed open-source project or public-repository contribution made during the hackathon window alongside the primary-track submission. Include contribution URL, project repository URL, GitHub username, and what changed, how it works, and why it matters. An unmerged branch, fork, or PR is acceptable.
- [optional/artifact] Optional: submit friction logs covering task, steps, expected versus actual result, severity, workaround, and actionable suggestion. These can receive up to a 10% judging bonus.
- [optional/artifact] Optional: include feature requests explaining the request, its importance, and priority as critical, important, or nice-to-have.
- Required technologies: Conditional on Fire TV entry: run on Fire OS or Vega OS; any framework or language is acceptable., Conditional on Alexa+ entry: working Agent Skill, self-hosted MCP server using specification 2025-11-25 or later over Streamable HTTP, or a working simulated Alexa+ experience using any AI or agentic tool. The simulation alternative has no mandatory framework, SDK, or MCP interface., Conditional on Bee entry: Bee CLI, MCP, or Agent Skills connected to actual data recorded and processed through a Bee device or Apple Watch running Bee software., Conditional on Ring entry: a Ring API, SDK, simulator, or device listed in Ring developer documentation., Conditional on AWS Builder entry: documented qualifying AWS integration or documented use of Kiro Crew during development; a separate AWS runtime service is unnecessary when qualifying through Kiro Crew.
- Encouraged technologies: Amazon Devices Builder Tools MCP server and Agent Skills for development assistance., Fire TV starter samples; React Native, web technologies, and Android Kotlin/Java are suggested implementation options., AWS services and tools such as Bedrock, AgentCore, Strands SDK, Kiro Crew, and SageMaker are optional outside AWS Builder., Cross-device integrations are permitted but are not mandatory.
- Build window: Participant execution planning assumption: approximately 10 focused build hours remaining, one developer starting from scratch, before 2026-10-23 20:00 Europe/London. Reserve additional time for recording and submission. Official qualifying dates remain in facts.

## Facts
- [high] The official submission period runs August 31, 2026 at 10:15 Pacific Time through October 23, 2026 at 12:00 Pacific Time. _(source: src-79e2639313c3; https://amazonappdev2026.devpost.com/rules)_
- [high] The deadline corresponds to October 23, 2026 at 19:00 UTC and 20:00 Europe/London. _(source: src-41e7f619fb22; supplied official rules and updates)_
- [high] Stage One is a pass/fail assessment of baseline viability, theme fit, and appropriate required-technology use. Stage Two uses four equally weighted criteria. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/rules, section 6)_
- [high] Friction logs are optional. Internal Stage One reviewers recommend a bonus up to 10%, which the Stage Two panel applies to the final spreadsheet score. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/rules, section 6)_
- [high] Ties are resolved by comparing criteria in listed order, beginning with Tech Implementation, then Design, Potential Impact, and Quality of the Idea; remaining ties go to a panel vote. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/rules, section 6)_
- [high] Judging is scheduled November 9–20, 2026, with winners announced on or around December 3, 2026. _(source: src-79e2639313c3; https://amazonappdev2026.devpost.com/rules)_
- [high] There is no maximum team size; solo entrants and organizations may enter. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/details/faqs)_
- [high] Gated Alexa+ Category SDK, MCP Toolkit, CLI, and Web Simulator access is unavailable to hackathon participants. The FAQ permits self-hosted integrations and entrant-built simulation/front-end paths. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/details/faqs)_
- [high] A locally runnable repository and demo video can satisfy Alexa+ judging access; an MCP server need not remain continuously live after submission. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/details/faqs)_
- [high] The October 7 update states that AWS promotional credit codes are exhausted and requests are no longer accepted. _(source: src-79e2639313c3; src-761412927b7b)_
- [high] Official rules take precedence over conflicting website, form, or promotional statements. _(source: src-41e7f619fb22; https://amazonappdev2026.devpost.com/rules, section 11)_
- [high] The operator supplies a one-developer constraint, approximately 10 focused build hours, and unconfirmed hardware/AWS runtime access. These are participant circumstances rather than official event rules. _(source: Operator constraints supplied directly in the task)_

## Inference
- Each Stage Two criterion represents 25% of the base evaluation. — The formal rules identify four equally weighted criteria; the optional friction-log bonus is separate.
- The crowding map can identify obvious or weakly differentiated archetypes, but cannot establish actual submission frequency. — The supplied materials contain organizer examples of obvious work but no representative gallery or competitor-project dataset.
- Bee eligibility has an unresolved participant dependency. — Real Bee-origin data is mandatory for that track, while the operator confirms neither compatible hardware nor access to that data.
- Promoted categories and creative examples are judging signals rather than compulsory project categories or technology stacks. — The rules distinguish priority categories and examples from the explicit track qualification requirements.
