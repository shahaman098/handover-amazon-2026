# Track feasibility under the current assumptions

Assumptions: solo developer, start from scratch, no confirmed hardware or privileged partner access, about 10 focused development hours. These assumptions can change if the participant supplies more resources.

| Track | Mandatory proof | Dependency that could stop delivery | Assessment before concept selection |
|---|---|---|---|
| Alexa+ | Working accepted Agent Skill, self-hosted MCP or entrant-built simulated Alexa+ experience; own source and functioning demo | Protocol implementation and meaningful application logic; no partner SDK needed | Most controllable path for the current time budget; still needs a distinct customer workflow |
| Fire TV | App actually running on Fire OS/Vega or an accepted emulator, shown in video | SDK/emulator installation and device-specific navigation/performance | Credible alternative if a specific TV-native interaction justifies the setup time |
| Ring | Documented Ring API/SDK/simulator/device integration functioning in demo | Developer onboarding, auth and actual available simulator capabilities | Good for event-driven accessibility or business workflows if an early integration spike succeeds |
| Bee | Actual Bee-origin data from a Bee device or Apple Watch running Bee, used by the application | No confirmed device or data access | Exclude from immediate build unless real data access is confirmed |

Sources: [official rules](https://amazonappdev2026.devpost.com/rules), [FAQ](https://amazonappdev2026.devpost.com/details/faqs), [resources](https://amazonappdev2026.devpost.com/resources).

Alexa+ and Fire TV each advertise first/second/third cash awards of $25,000/$15,000/$4,000; Ring and Bee advertise $12,000/$8,000. Prize size is not a probability estimate or evidence of lower competition in another track.

AWS Builder and Open Source are optional additions to a primary-track submission. Do not allow an extra category to prevent completion of the primary project. Kiro Crew development use can independently qualify for AWS Builder if actually used and documented. The Open Source category requires an additional qualifying project/contribution alongside the primary entry; an open-source primary repo alone should not be assumed sufficient.
